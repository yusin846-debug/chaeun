# 채운 개발 순서

## 확정된 진행 방식

2026-09-28 사용자가 ‘목업 확정 → 실제 웹 구현’을 재확인했다. 이전에 생성한 가구 쇼핑몰 형태의 목업은 승인본이 아니다. 제품 화면 코드는 목업 승인 후 변경한다.

## 현재 코드에서 확인한 사실

- 기존 Next.js 웹앱과 Motion 기반 화면이 있다.
- 홈 CTA에서 /create로 가면 추가 소개 화면이 나온다. 실제 구현에서는 새 상담 시작 시 생년일시로 바로 연결해야 한다.
- 현재 오행 계산은 숫자를 조합한 모의 계산이다.
- 실제 사주·채팅·결제·이미지 생성 API 연동은 아직 확인되지 않았다.
- GitHub Issues 조회 결과 기존 이슈가 없었다. 작업 분해는 사용자 승인 후 GitHub Issues #1~#7로 게시했다.

## 승인된 순서

### 0. 사진 및 랜딩 목업 확정

선행: 없음.
산출물: 메인 방 사진, 동일 소품의 디테일, 워드마크·한글 타이포, 데스크톱과 모바일의 기본/조명 이동/카드 중첩 상태. 짧은 영상은 사용할 위치와 장면을 먼저 확정한다.
완료: 사용자가 시안을 확정한다. 생성 이미지는 구조·재질·광원·동일성·모바일 잘림을 검사한다.

### 1. 히어로에서 생년일시 입력까지

선행: 0.
산출물: 승인한 히어로를 실제 웹에서 보고, 데스크톱 포인터/모바일 스크롤로 빛을 움직이고, CTA로 생년일시 입력에 바로 진입한다.
검증: 모바일/데스크톱 실제 화면, CTA 경로, 키보드 조작, 모션 줄이기. 폼과 서비스의 실제 분석 연동은 후속 작업이다.

### 2. 랜딩 전체 탐색

선행: 1, 사용할 미디어 승인.
산출물: 소재의 호버·탭 사진, 색/소재/공간 카드 중첩, 짧은 무음 영상, 메뉴와 갤러리까지 탐색하고 어느 지점에서든 상담 시작 가능.
검증: 화면 밖 영상 정지, 모바일 대체 조작, 영상 미재생 시 사진, 카드 가독성, 안정적인 레이아웃.

### 3. 생년일시에서 실제 사주 해석까지

선행: 1, 사주 계산 기준·제공 방식 결정.
산출물: 사용자 입력을 검증하고 실제 계산 결과에 근거해 일간과 오행을 표시한다. 시간 모름·양음력·출생지/시간대 정책을 정한 뒤 구현한다.
검증: 기준 사례와 대조, 경계 날짜/시간, 불확실한 입력 처리. 모의 숫자를 실제 분석으로 전달하지 않는다.

### 4. 상담 펫과 여섯 고민의 대화 시작

선행: 3, 펫 외형·말투·대화 엔진 결정.
산출물: 펫이 직접 해석을 말하고 사용자가 여섯 고민 중 선택하거나 직접 입력한다. 첫 상세 상담은 연애이되 다른 주제를 연애로 바꾸지 않는다. 대화/분석 상태와 펫 반응이 연결된다.
검증: 주제 진입, 답변 보존, 재시도/뒤로가기, 연애 3~4회 왕복과 중간 정리.

### 5. 상담에서 풍수 맥락과 개인화 공간 결과까지

선행: 4, 지역 해석과 이미지 생성 방식 결정.
산출물: 중간 정리→동네/창/주거 정보의 복수 선택·직접 입력·건너뛰기→방 이미지·소품·동네 제안·결과 대시보드.
검증: 입력의 실제 반영, 누락 대응, 생성 실패와 재시도, 결과 안 대시보드, 포스터와 방 이미지 구분.

### 6. 저장·공유 특전·990원 보완 아트

선행: 5, 공유 인정 방식·결제 제공자·소장 정책 결정.
산출물: 방 이미지 저장·공유에서 특전 안내, 공유 특전 또는 실제 결제 후 보완 아트 생성·다운로드. 후속 쇼핑 추천 연결.
검증: 취소/실패/중복 결제/생성 재시도, 실제 파일 저장, 포스터 저장이 결과 첫 화면에 나오지 않음. 주문 접수 안내는 실제 성공 뒤에만 표시.

## 진행 원칙

각 작업을 완료할 때 실제 화면이나 검증 가능한 결과를 보여주고 다음으로 넘어간다. 필요한 결정은 해당 단계 직전에 묻는다. 코드 검증은 사용자 동작 중심의 브라우저 검증과 타입·빌드 검사, 실제 계산/결제의 서비스 경계 검증으로 나눈다. 미정 상태의 후속 작업은 ready-for-agent로 게시하지 않는다.
